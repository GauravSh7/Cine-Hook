## Contract decisions

1. Add nullable unique `User.googleSubject` and allow nullable `passwordHash` for a genuine Google-only account. Existing passwords/roles remain untouched. Password login explicitly rejects missing hashes after dummy timing work. Identity lookup is by verified Google subject. Existing email collisions return a safe conflict requiring existing password login; no automatic linking or merge. Explicit linking is not necessary for this delivery.
2. Google routes: `GET /api/auth/google/config`, `POST /api/auth/google/challenge`, `POST /api/auth/google`. Configuration returns only a public web client ID. Challenge uses a short-lived signed HttpOnly same-site cookie, independent nonce and CSRF token, exact Origin binding and token-purpose separation. Validate challenge before provider verification and match the verified token nonce. Clear the cookie after submission; do not claim globally single-use stateless challenges.
3. Movie additions: nullable `backdropUrl`, safe stored collection keys, metadata source, artwork provenance and nullable verified rating provenance. Fixture ratings are null. Public Movie DTO exposes `artwork`, `rating` and server-derived `bookingAvailability` consistently; raw rating columns are not public. Ordinary admin inputs cannot supply verified rating fields.
4. `GET /api/movies` and `GET /api/movies/:id` accept optional validated `cityId`; `bookingAvailability` checks active scheduled future shows in that city (or explicitly all cities). Add `GET /api/movies/:id/show-dates?cityId=...` returning `{ dates: string[], timeZone: 'Asia/Kolkata' }` from all upcoming dates, independent of pagination. Preserve existing UTC `date` query. Add separate `localDate=YYYY-MM-DD` to `/api/shows`, interpreted as an IST calendar day; reject simultaneous `date` and `localDate`.
5. Exactly 30 fixture films: preserve the first six manifest keys, IDs and ordering; append 24 verified Hindi/South/English titles. Preserve the existing 18:30 IST schedule. Add a stable 10:00 IST slot to each of six screens, rotating its four appended films by absolute IST calendar-day ordinal modulo four. Seven future days cover every appended film. Keep prices/layout/admin/user and financial history unchanged. Fixed-clock fresh totals: 30 movies, 3 cities, 3 theatres, 6 screens, 288 seats, 84 shows, 252 prices. Moving-clock reruns retain history and may append dates.
6. Original native SVG cinematic illustrations are the self-contained fallback, not official posters. Keep safe local artwork URLs restricted to the controlled `/demo-art/...svg` namespace. Never broadly allow local paths or arbitrary schemes. Existing seed-managed legacy references may be replaced only by exact-ID/exact-known-old-value conditional enrichment; custom/naturally reused movie records are preserved.
7. IMDb is not scraped or republished from unlicensed datasets. Optional TMDB import is development-only, server-token based, exact-ID selected, source-attributed, cached with a bounded rating lifetime and safe on provider failure. No credential means no provider rating. Provider tokens never appear in frontend variables or logs.
